# Experiment Plan：JAPD-16

**Problem**：在保留DFlash完整16位一次并行生成的前提下，用轻量global non-causal
head显著提高accepted length；fixed/dynamic EAL与同栈SGLang吞吐最终均至少达到
same-job released Domino的`1.15x`。

**Method Thesis**：固定full16 global scorer不变，JAPD通过all-prefix non-vanishing
distillation和保守two-frontier joint certificate，让同一次唯一链输出共同修复前两处
及更多早期错误，而不增加在线步骤。

**Date**：2026-08-10

## Immutable execution contract

- online输入必须是完整`[B,16,*]` DFlash features与每位置pure-base Top16；
- global arm每个位置通过无causal mask的mixer看到全部16位；
- 一次head call输出`[B,16,16]`，一次逐位置argmax得到唯一`[B,16]`链；
- 禁止GRU/selected-token feedback/autoregressive或serial target seed/iteration/Jacobi/
  beam/tree/trie/forest/multipath/额外online target inference；
- 默认D64/H4/L1、`433,852`参数；D256只能按双门AND规则在fresh300前统一切换三臂；
- frozen loss：`T=2`、hard/soft=`0.9/0.1`、`Z=136`、
  `L=L_AP+L_J2`、无可调mix weight；
- 任何后一阶段只在前一阶段所有hard gate通过后启动。

## Paper Storyline

- **Main paper must prove**：fresh机制隔离；100K→final600 fixed/dynamic主结果；同栈
  SGLang吞吐。
- **Appendix can support**：mechanics/capacity/latency完整表；J2/位置/域别失败分析；
  预注册objective deletion ablation。
- **Experiments intentionally cut**：所有serial/GRU/tree/beam/multipath/iterative路线；
  target early-exit/seed；大规模LR/width sweep；为了“救结果”的post-hoc loss权重；
  无助于EAL/TPS的运行时hash门；旧R050–R056 off-spec系统结果。
- **Frontier block**：本方法刻意不依赖在线LLM/VLM/RL primitive；target distribution
  只作offline label，因此不强行设置frontier-necessity实验。

## Experiment Blocks

### Block 0：Compliance、capacity与公平latency

- **Claim tested**：实现确实是full16 global parallel one-chain；D64能优化；成本足够轻。
- **Why**：在任何效果实验前排除off-by-one、target leakage、空J2门和不公平计时。
- **Dataset / split**：R047 train；512个label-independent、domain-stratified prompts，
  每prompt一个固定block；strict multi-repair denominator必须`>=256`。另用不重叠的
  512 fit prompts作full-fit diagnostic。
- **Compared systems**：D64 global-JAPD；released Domino eager；DFlash base。
- **Decisive metrics**：step0 identity；shape/token invariants；bidirectional remote-position
  visibility；same-set J2、oracle-gap recovery、harm；complete p50/p90/mean与peak memory。
- **Secondary metrics**：gradient norm、AP/J2 loss、每位置accuracy、incremental-only latency。
- **Setup**：A40、BF16、batch1 profile；capacity batch16、seed0；complete path严格包含
  base vocab GEMM→FP32 logsumexp→Top16→gather→head→argmax。sidecar由DFlash/shared
  vocab projection生成；Top16 IDs、stored-dtype logits、LSE/scalars/token replay
  fail closed。
- **Success**：finite；参数`433,852`；输出`[B,16,16]`且唯一链；target cache字段未被
  loader读取；J2`>=99%`、oracle-gap recovery`>=95%`、harm`<=1%`；complete
  `<=1.20x`eager Domino。
- **Capacity rule**：D64 full-fit gate pass=`J2>=90% AND oracle recovery>=80%`。
  只有same-set capacity和full-fit gate均失败，才允许三臂在fresh300前统一切D256；
  其它情况保持D64。
- **Failure interpretation**：合规/parity/latency失败先修实现再复跑同一门；capacity与
  full-fit同时失败才是underfit；capacity通过而heldout失败是transfer failure，禁止加参。
- **Table target**：Appendix implementation/cost table。
- **Priority**：MUST-RUN。

### Block 1：Fresh300 matched mechanism isolation

- **Claim tested**：global information与JAPD objective各自提供真实、可泛化净增益。
- **Why**：这是最小、最高价值的机制falsifier，防止直接烧100K数据。
- **Dataset / split**：R047 1,987 prompts按domain内canonical-ID排序后以seed`20260810`
  label-independent shuffle，固定fit/select/diagnostic=`1589/199/199`；另在采label前
  冻结fresh300（chat/code/math各100），排除所有历史manifests及text near duplicates。
- **Compared systems**：global-JAPD、parameter-matched local-JAPD、global-Candidate-
  D-PACE(`alpha=0.5`)；外部报告DFlash base、released Domino、PGCF-v1。
- **Metrics**：prompt-balanced EAL；paired prompt bootstrap10K/seed20260810；strict
  J2（denominator需报告）；prefix harm；每域EAL；suffix-only edits。
- **Setup**：三臂同容量、初始化、fit/select、batch order、epochs与sidecar；D64默认；
  batch16、AdamW`3e-4`、WD`1e-2`、warmup200、cosine至`3e-5`、最多6 epochs、
  eval250、seed0；checkpoint仅按internal-select EAL、tie取早。fresh300只评一次。
- **Success（全部）**：global-local与global-DPACE均`>=0.15 EAL`且paired CI lower`>0`；
  global EAL`>=7.55`；每域`>=base`；J2`>=Domino`且比两个control各高`>=10pp`；
  harm`<=Domino`。
- **Failure interpretation**：任一失败立即关闭exact JAPD route；不得加数据、改loss、
  加参或转serial/tree。J2升而EAL不升视为early harm/后续错误抵消，主目标仍失败。
- **Table target**：Main Table 1（mechanism）与J2 gain figure。
- **Priority**：MUST-RUN。

### Block 2：Scale、untouched fixed/dynamic主结果

- **Claim tested**：机制可扩展到最终EAL目标并转移到dynamic rollout。
- **Dataset / split**：25K与100K OPB prompts及其internal selects，显式排除fresh300与
  final600 IDs/near duplicates；final600（每域200）在method/recipe/seeds冻结前只
  冻结manifest、不读取outcome。
- **Compared systems**：JAPD final、released Domino、DFlash base；PGCF-v1只作历史参考。
- **Setup / run order**：
  1. 仅global-JAPD seed0训练25K；
  2. 25K过门后训练100K seeds`0,1,2`；每seed checkpoint只看100K internal-select；
  3. deployment seed在打开final600前按internal-select EAL的三seed中位数确定，tie取
     seed编号小者；不得看final选seed；
  4. 三seed均过internal opening gate后，一次性评估final600 fixed/dynamic并完整报告。
- **25K hard gate**：EAL`>=max(7.80,1.075x same-job Domino)`；每域`>=base`；
  J2`>=same-job Domino`。失败即关闭。
- **100K opening gate**：三个seed各自fixed EAL均
  `>=max(8.3254859086,1.15x same-job Domino)`，且每域不低于base；任一seed失败
  不打开final600。
- **Final decisive metrics**：预选deployment seed的prompt-balanced fixed/dynamic EAL
  均`>=1.15x`same-job Domino；每域不退化；paired bootstrap CI；三seed结果全部报告，
  三seedmedian也必须`>=1.15x`Domino，任一seed不得低于Domino。
- **Failure interpretation**：25K失败说明scale slope不足；100K失败说明方法不足以达到
  主目标；fixed过而dynamic失败说明rollout shift未解。三者均禁止进入SGLang claim。
- **Table target**：Main Table 2（fixed/dynamic、domains、seeds）与scaling curve。
- **Priority**：MUST-RUN，仅前门通过后。

### Block 3：Same-stack SGLang end-to-end

- **Claim tested**：accepted-length增益在真实服务中转化为至少15%吞吐优势。
- **Dataset**：同一final600的固定prompt/token manifest；不根据系统结果删prompt。
- **Compared systems**：同checkout、同backend、同batch/request、同A40的released
  Domino与deployment JAPD；DFlash base作secondary reference。
- **Metrics**：paired per-prompt tokens/s ratio与95% CI、aggregate TPS、latency p50/p90/
  p99、EAL、显存；输出token parity相对同栈target-only greedy。
- **Setup**：ordinary one-chain verifier；相同CUDA graph/Triton优化等级；完整head path
  含LSE/Top16/gather/argmax；warmup、prompt order与ABBA server restart固定。
- **Success**：lossless/stable output parity；paired TPS ratio 95% CI lower`>=1.15`；
  同system run的EAL仍满足final acceptance门。
- **Failure interpretation**：若EAL通过但TPS失败，系统claim失败；只允许优化同一冻结
  并行head kernel，不得改method/候选/生成方式，优化后仍须重跑完整公平门。
- **Table target**：Main Table 3（E2E）与EAL–TPS Pareto图。
- **Priority**：MUST-RUN，仅B2通过后。

### Block 4：Objective deletion与failure anatomy

- **Claim tested**：JAPD两个部分都必要，完整方法不是任意weighted CE包装。
- **Why**：防止审稿人将贡献解释为普通dense CE；但不应延迟主门。
- **Dataset**：仅development/internal diagnostic；绝不用于checkpoint或final选择。
- **Compared variants**：frozen full JAPD；AP-only（删J2）；J2-only（删AP）；global-
  D-PACE。所有其它配置完全一致。
- **Metrics**：EAL、strict J2、first/second/third correction recovery、prefix harm、按
  first-error位置与margin分桶。
- **Success**：full JAPD同时具有最高EAL与J2，且删除任一项出现预期机制退化；不设
  进入主结果的救援门，也不据此改mix weight。
- **Failure interpretation**：若一个组件无贡献，论文claim收窄；不得看结果后重调loss。
- **Table target**：Appendix ablation与failure heatmap。
- **Priority**：NICE-TO-HAVE；仅B2成功后运行。

## Compute and Data Budget

- **Total must-run estimate**：约`30–87 A40 GPU-hours`，但fail-closed gates通常会在
  `3–12 GPU-hours`内终止无效路线。
- **Data preparation**：现有R047 train/select sidecar；fresh300/final600/25K/100K
  label-independent manifests；新collector直接存base LSE并拒存/拒载online不可用target
  features到head batch。
- **Storage**：sidecar只存FP32`[16]` LSE与identity，canonical rollout不改写；大规模
  collection沿现有sharded格式。
- **Human evaluation**：不需要。
- **Biggest bottleneck**：不是head参数或latency，而是frozen DFlash lattice能否从在线
  full16 features辨识第二处及后续gold candidate。

## Risks and Mitigations

- **Joint certificate过强**：先用same-set/full-fit gates观察AP/J2梯度、harm与margin；
  失败按预注册关闭，不post-hoc加weight。
- **Transfer failure重现**：fresh300三臂是100K前的硬falsifier；不以same-set容量替代。
- **Data contamination**：在采label前做ID与normalized-text排除并固定manifest；不做无意义
  runtime cryptographic gate。
- **Target leakage**：batch schema whitelist；明确拒绝`target_anchor_early_feature`等字段；
  tests检查forward signature与dataflow。
- **Unfair latency**：complete path计入LSE reduction/Top16/gather/argmax，Domino同eager栈；
  最终SGLang同优化等级。
- **Final seed shopping**：deployment seed按100K internal中位数在打开final600前冻结。
- **Dynamic failure**：fixed不能替代dynamic；dynamic失败不进入系统claim。
