# FINAL PROPOSAL: GFPR

**Status:** ARIS research-refine READY (9.20/10)  
**Route:** Greedy-Frontier Policy Replay for Domino  
**Date:** 2026-08-09

## Problem Anchor

- 主目标是完全解决接受长度不高，而不是包装小幅提升。
- released Domino exact B16 held-out EAL 为 7.23955；历史 fixed-position-0 Top-16 oracle 为 10.25449。
- 方法相对 537.4M draft 必须轻量；最终必须以更长接受长度换来相对 Domino 约 15% 端到端吞吐。
- 成功要求：untouched fixed exact-runtime EAL ≥8.325，真实 dynamic rollout EAL ≥1.15× released Domino，并通过 paired uncertainty 与 harm gates；之后才进入 SGLang。

## Dominant Thesis

Exact-greedy block-parallel draft 应只在真实 policy 到达的 verification anchors 上，保护当前已接受前缀并修复当前首个 rejection，且必须覆盖 released interface 无法修正的 position 0。

核心诊断是：

1. 既有训练 anchors 是固定 target-clean offsets，不是部署中按 accepted draft tokens 加 target bonus 到达的状态；
2. 首错后的 suffix 对本轮 EAL 无收益，却长期占据监督；
3. released Domino position 0 直接使用 parallel base top-1，held-out 有约 11.8% blocks 在后续 head 可作用前已失败。

## Unified Stages A–C Policy

Stages A–C 只使用 direct full-vocabulary adapted Domino policy：

\[
d_i^\theta=\arg\max_{v\in V}s_i^\theta(v).
\]

- 位置 1–15 复用现有 Domino GRU/correction head。
- 每个 block GRU 清零并先消费 anchor。
- 位置 0 复用同一 correction head，score 为 base_0 加 α_0 correction_0，且 α_0=0 初始化。
- selected position 0 进入 GRU 后供 position 1 使用，之后按实际 selected tokens 因果递推。
- released head 权重加 α_0=0 必须逐 token 复现全部 16 位 released policy。
- 训练后直接 full-vocabulary argmax；没有 candidate mask、第二套 frozen head或 candidate-truncated KL。

可训练部分是已有约 50.8M Domino causal head加一个标量。新增推理算术是第 16 次完整 correction-head 调用，必须实测。

## Exact Rollout Semantics

对 cycle m，verified context 为 c_m，draft selections 为 d_m：

\[
g_{m,i}=\arg\max_v T(v\mid c_m,d_{m,<i}),\qquad
r_m=\min\{i:d_{m,i}\ne g_{m,i}\}.
\]

- i<r_m 和首错 i=r_m 是 clean reachable states；
- 首错后的 wrong-prefix suffix 不参与训练；
- runtime 接受 r_m 个 draft tokens，再追加 target correction/bonus；
- 下一 anchor offset 严格是 o_{m+1}=o_m+r_m+1；
- r_m=16 时仍生成 position-16 target bonus，它进入 context 并成为下一 anchor。

## Collector

从 phase3/OpenPerfectBlend prompt或已有 nested canonical continuation还原 prompt 与 target-greedy continuation。每 prompt 一次 target causal pass，然后用完全相同 drafting code 采两种 records：

- dynamic：从 offset 0 按当前 policy 的 r+1 递推；
- fixed-control：同一代码在预定 fixed offsets 运行。

保存 raw context 索引、policy version、anchor offset、full-16 hiddens、selected tokens、clean continuation和accepted length。只做 first mismatch、r+1 与 full-accept bonus 等语义检查。

## Current-Frontier Objective

在每个 clean block 上用当前参数重新寻找首错 q_θ。其前缀当前都预测正确，因此 teacher-prefix GRU state 与真实 policy state 相同；首错后不产生 loss。

\[
L =
\lambda_{break}\mathbf 1[q_\theta<16][m_{break}-\Delta_{q_\theta}]_+
+
\frac{\lambda_{keep}}{\max(q_\theta,1)}
\sum_{i<q_\theta}[m_{keep}-\Delta_i]_+
+
\lambda_{wd}\|\theta-\theta_0\|_2^2.
\]

默认 λ_break=1.0、λ_keep=0.1。prefix 保护按 block 归一化，prompt 内所有 cycles 总权重归一为 1。修好首错后，同一 block 下一次 forward 自动暴露更后的 frontier。

## Policy Refresh

1. v0：released Domino actual rollouts；
2. Gate B 通过后，用选定 checkpoint 重采 v1 anchors；
3. 扩展训练按 prompt 混合 50% v0 和 50% v1；
4. 一次 refresh 负责暴露新的跨-cycle frontier，不做无限 DAgger。

## Gate A — Feasibility

1. 复现 full-16 released identity和历史 7.23955；
2. 计算 all-16 DFlash Top-16、K17、K16 oracle及 position-0 增量；
3. 验证 dynamic r+1、GRU reset、r=16 bonus；
4. profile第16次 full-vocabulary head 调用。

Top-16/K16 只作 oracle 和可选 contraction。若 Stage D 最终采用 K16，使用冻结 Stage-C scorer 重算的 all-position K16 oracle 必须 ≥8.825。

## Gate B — 2K-Prompt Causal Screen

同 prompt、budget和代码比较：

1. fixed anchors，位置1–15；
2. dynamic anchors，位置1–15；
3. dynamic anchors，all-16 GFPR。

继续门：fixed held-out EAL ≥7.55、相对 released ≥+0.30、paired prompt-bootstrap 95% lower bound >0、lost accepted tokens ≤0.5× gained tokens、harmful prompts ≤20%。若 EAL ≤7.40 或 alignment 正确时持续退化，终止当前 head/objective 路线。

## Gate C — Scale and Refresh

Gate B 通过后才扩到16K–32K prompts并执行一次refresh。只有 fixed exact-runtime EAL ≥8.325、true dynamic rollout ≥1.15× Domino、paired lower bound >0且harm gates通过，才算主问题解决。

## Conditional Gate D

仅当GFPR已有显著held-out信号但低于目标时，才比较candidate-conditioned lightweight residual与draft最后一层/LoRA。LoRA/backbone arm必须在线重算或重采hiddens。

## Gate E — System Result

EAL达标后再集成SGLang/CUDA Graph。在同硬件、batch和workload下报告draft/head/verify latency、EAL和tokens/s，目标相对Domino端到端吞吐约15%或更高。

## Claims

- Primary：policy-induced reachable-frontier replay plus all-16 correction materially closes Domino的greedy acceptance gap。
- Supporting：增益首先来自训练状态/目标对齐，而不是再堆一个大head。
- Anti-claims：不声称当前objective支持sampling；不把DAgger、margin、GRU、Top-K或Draft-OPD单独包装为新颖。
