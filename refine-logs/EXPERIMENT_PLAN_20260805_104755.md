# PROS-Gate Claim-Driven Experiment Plan

**Problem：** Frozen Direct 在 DFlash 上有正的平均收益，但 1,175 个 development blocks 中同时存在 141 个 beneficial、62 个 harmful 和 972 个 neutral blocks；无条件 APPLY 无法回收足够的二元 oracle gap，而 226-action CAMRS 又因 harmful-score 极值尾部过度编辑。  
**Method Thesis：** 复用 frozen Direct 的全局上下文状态，用一个 exact-identity、38,674 参数的 block-level sidecar 只学习 KEEP DFlash / APPLY Direct，可在 producer-out-of-sample prompts 上预测条件期望 token gain，同时避免 action-level max tail。  
**Date：** 2026-08-05  
**Normative method：** `refine-logs/direct-safety-gate/FINAL_PROPOSAL.md`

## Claim Map

| Claim | Why It Matters | Minimum Convincing Evidence | Linked Blocks |
|---|---|---|---|
| C1（primary）：PROS-Gate 能在 producer-OOS 数据上安全地选择 frozen Direct，而不是在 Direct 与 DFlash 之间做无条件选择 | 这是从 CAMRS 失败得到的唯一核心机制 claim | one-shot 200-prompt falsifier 上 recovery ≥0.90，EAL 严格高于 DFlash 与 Direct，harm≤5%，first-token 比 Direct 至多少1，所有 recovery/bound/provenance 检查通过 | B1-B3 |
| C2（supporting）：收益来自复用 contextual Direct states，而非常数策略或手工 scalar threshold | 防止把结果解释成更多参数、后验阈值或简单 margin rule | frozen 21-scalar ridge、always-KEEP、always-Direct 全部预先冻结；PROS recovery 至少高于最佳 comparator 0.05；raw `z>0` 无 threshold sweep | B2-B3 |
| Anti-claim：capacity 记忆、producer in-sample labels、后验 calibration 或更大模型即可解释结果 | 约束 claim 边界与 researcher degrees of freedom | capacity 明确只作 plumbing；fit/checkpoint/falsifier prompt-disjoint；OPB labels 不训练 gate；无额外 seed/width/threshold rescue | B0-B4 |

最多保留以上两个正向 claim。该路线不主张新的 hinge、selective prediction、routing、attention 或 calibration 理论。

## Paper Storyline

- Main paper 必须证明：二元 safety decision 消除 CAMRS 的 max-over-actions failure mode，并在严格 producer-OOS falsifier 上同时回收收益与控制 harm。
- Appendix 支撑：exact identity、特征/池化/梯度隔离、容量记忆上界、scalar comparator、完整 denominator/provenance replay。
- Conditional development：`validation_select` 只验证该方法能否达到已知 DFlash/Direct target；它已参与历史模型开发，不是 claim-grade untouched evidence。
- Frontier necessity：本方法没有独立的 frontier-model primitive claim；Qwen3/DFlash 只是 frozen system context，因此不强行增加 LLM judge、RL、VLM 或 diffusion 对照。
- Intentionally cut：threshold/calibration sweep、D640/wider sidecar、额外 seed、OPB in-sample gate training、formal test、online rollout、联合训练 producer、第二个路由 action、falsifier 后 refit。

## Experiment Blocks

### Block 0：CPU semantics 与 fresh acceptance

- Claim tested：实现是否精确等价于 normative PROS-Gate，且所有 fail-closed metric 口径可独立重放。
- Why this block exists：前一审查周期发现 false-APPLY denominator、first-token witness 与 recovery reconstruction 缺陷；真实数据前必须由新 reviewer 验证最终哈希。
- Dataset / split / task：仅 synthetic CPU fixtures；禁止打开任何 canonical split。
- Compared systems：epoch-zero identity、nonzero positive/zero/negative sidecar、manual pool/loss/replay oracle。
- Metrics：33 focused tests、261+3 full suite、py_compile、diff check、pinned producer hashes、I/O/CUDA static isolation。
- Setup details：D64/H4/L1 axial-additive L15/K16 synthetic producer；当前 sidecar/protocol/test 哈希重新冻结。
- Success criterion：fresh independent xhigh reviewer 对最终代码给 bounded GO，并明确只授权下一阶段 artifact implementation/review。
- Failure interpretation：任何 blocker 都留在 CPU；不得用本地测试替代 external acceptance。
- Table / figure target：Appendix implementation assurance table。
- Priority：MUST-RUN。

### Block 1：producer-OOS split/outcome artifact 与 capacity plumbing

- Claim tested：数据边界、frozen Direct outcomes、capacity selection 和训练管线是否实现正确；本 block 不支持泛化 claim。
- Why this block exists：先排除 leakage、identity、outcome reconstruction、optimizer 和 checkpoint-selection 错误，再承担 falsifier 成本。
- Dataset / split / task：
  - Phase-3 canonical `train`：1,987 prompts / 15,886 blocks；
  - hash split：fit/checkpoint/falsifier = 1,587/200/200 prompts，domain counts 严格为 chat 523/66/66、code 531/67/67、math 533/67/67；
  - 在任何 outcome computation 前冻结 split manifest；
  - 证明与 OPB producer prompts、`validation_gate`、`validation_select`、reserved/formal sets 零 sample-ID overlap；
  - physically separate fit、checkpoint、falsifier artifacts；trainer API 无 falsifier path。
- Compared systems：fresh PROS sidecar、epoch-zero KEEP identity；capacity 不比较 paper baselines。
- Metrics：
  - native Direct scores/path/state/output bitwise witness；
  - base/Direct lengths、gain、first-token、block key、prompt/domain counts；
  - 512 prompt-unique capacity composition：256 beneficial、128 harmful、128 changed-neutral；
  - capacity selected checkpoint 的 loss、benefit recall、harm avoidance、utility optimality、recovery、harmful APPLY、regret-bound violations。
- Setup details：
  - producer job10133585 checkpoint `9486d976…d6d9a0e`、metrics `9ec91a1f…ad4aef`；
  - batch32，320 complete passes，5,120 updates，AdamW lr6e-4、betas(.9,.999)、eps1e-8、wd0、clip1、warmup205、cosine、seed0；
  - exact `1/512` probability masses，earliest full-precision minimum among 321 checkpoints。
- Success criterion：selected checkpoint 自身满足 loss≤5% epoch0、benefit≥254/256、harm avoidance≥127/128、utility≥509/512、recovery≥0.95、harmful APPLY≤1、所有值/梯度 finite 且零 bound violation。
- Failure interpretation：失败只说明 exact sidecar/pipeline 未在 adaptive same-subset 上形成充分 witness；关闭本路线，不进入 fit，不改 threshold/width/seed。
- Table / figure target：Appendix capacity/plumbing table。
- Priority：MUST-RUN。

### Block 2：clean fit、checkpoint-only selection 与 frozen comparators

- Claim tested：sidecar 是否能从 producer-OOS fit prompts 学到可迁移到 checkpoint prompts 的 contextual gain decision。
- Why this block exists：capacity 可记忆，真正风险是 contextual separability。
- Dataset / split / task：仅 fit 更新参数；仅 checkpoint 选择；falsifier artifact 保持未打开。
- Compared systems：
  1. PROS-Gate；
  2. float64 prompt-weighted 21-scalar ridge（ridge=1e-3）；
  3. always-KEEP；
  4. always-Direct。
- Metrics：prompt-balanced EAL、gain hinge、harm count、recovery、benefit recall、harm avoidance、neutral APPLY、utility optimality、first-token、domain slices。
- Setup details：
  - fresh seed0 sidecar；
  - batch64，最多5,120 updates；
  - 若 `S=ceil(fit_blocks/64)`，运行 `floor(5120/S)` 个完整 passes，无 partial pass；
  - deterministic SHA order；half-up 4% warmup；AdamW lr6e-4、wd/dropout0、clip1；
  - checkpoint strict lexicographic key `(EAL,-harmed_count,-hinge)`，ties 取最早；
  - ridge 只在 fit 拟合并与 selected sidecar 一起 hash-freeze。
- Success criterion：产生唯一、可重放、recovery-valid 的 selected checkpoint 与 frozen comparator bundle；本阶段不以 fit behavior 宣称成功。
- Failure interpretation：若所有非 identity checkpoints recovery invalid，或 selected checkpoint 是 identity，仍可按原协议进入 falsifier，但预期 claim 风险极高；不得改 selection key。
- Table / figure target：checkpoint trajectory appendix figure。
- Priority：MUST-RUN。

### Block 3：one-shot contextual falsifier

- Claim tested：C1 与 C2。
- Why this block exists：这是在打开历史 development set 前唯一不可适配的判决。
- Dataset / split / task：200 prompts 的 frozen falsifier，一次打开；selected sidecar/comparators 不得 refit。
- Compared systems：PROS、DFlash、frozen Direct、21-scalar ridge、always-KEEP、always-Direct。
- Metrics：完整 EAL/token mass、recovery、harm fraction、first-token、APPLY composition、benefit recall、harm avoidance、neutral/tie/false-APPLY、oracle regret、score/gain quantiles、domain slices、10,000-replicate deterministic prompt-cluster intervals。
- Setup details：raw `APPLY iff z>0`；独立 saved-record reconstruction；start/end hashes；scientific failure先原子写完整 JSON再 nonzero exit。
- Success criterion（全部 conjunctive）：
  - finite values、零 regret-bound violations；
  - finite positive oracle denominator，unclipped recovery∈[0,1+1e-6] 且≥0.90；
  - EAL 严格高于 DFlash 与 Direct；
  - harmed fraction≤0.05；
  - first-token count 比 Direct 至多低1；
  - recovery 至少高于最佳 frozen scalar/constant comparator 0.05；
  - exact split/producer/feature/checkpoint/native-Direct identities。
- Failure interpretation：关闭 exact PROS route；禁止 threshold、refit、longer/wider、alternate split、extra seed、OPB labels 或 validation rescue。
- Table / figure target：Main result table + decision calibration/failure histogram。
- Priority：MUST-RUN。

### Block 4：conditional development 与系统代价

- Claim tested：通过 falsifier 的同一 frozen sidecar 是否达到现有 DFlash/Direct development target；context reuse 是否保留可接受系统成本。
- Why this block exists：验证当前项目目标，但不把历史 `validation_select` 包装为 untouched evidence。
- Dataset / split / task：仅在 reviewed falsifier PASS 后一次打开 147-prompt / 1,175-block `validation_select`；不训练、不选 checkpoint。
- Compared systems：DFlash、Direct-native、Direct-one-edit、PROS；latency 对比 DFlash/Direct/PROS unfused sidecar。
- Metrics：EAL deltas、harm、first-token、recovery、exact controls；producer+sidecar head latency、memory；如果以后实现 fused capture，另行 review。
- Setup details：same frozen checkpoint/hash；无 calibration；prompt-cluster interval 只作 development uncertainty。
- Success criterion：`EAL_PROS-EAL_DFlash>0.28499`，比 Direct-native 与 Direct-one-edit 均≥0.05，harm≤5%，first-token shortfall≤1/1175，recovery valid，零 bound violations。Latency 只决定 systems claim，不可挽救 efficacy failure。
- Failure interpretation：development gate 失败则报告 negative；EAL 正但 latency 负时最多保留 offline selector evidence。
- Table / figure target：Development control table；latency appendix。
- Priority：MUST-RUN after B3 PASS；fused optimization 是 NICE-TO-HAVE 且需新 proposal/review。

## Compute and Data Budget

- Pre-development upper estimate：≤1.1 GPU-hours；conditional development/latency 后总计≤2.1 GPU-hours。
- Data preparation：读取一次 Phase-3 canonical train collection；split identities before labels；输出 physically separate、content-addressed fit/checkpoint/falsifier records。
- Storage：预估 200-d float32 features 约 12 MB/1,000 blocks；保存 producer states/features、outcomes、identity/provenance 后应远低于现有 Phase-3 collection。
- Human evaluation：none。
- Biggest bottleneck：不是算力，而是 1,587 fit prompts 下 harmful/beneficial contextual separability，以及 binary-oracle slack 仅 0.033766 EAL。
- Budget rule：任何任务超过预估 wall time 2×，先读 primary logs 并停下审计，不提交 unchanged retry。

## Risks and Mitigations

- Leakage：split manifest 在 outcome computation 前冻结；artifact writer 与 trainer split allowlist 分离；falsifier path 不出现在 fit CLI。
- Metric self-confirmation：训练输出与 saved-record adjudicator 独立；result reviewer 从 records 重算全部分母/EAL/recovery。
- Capacity overinterpretation：capacity 只决定 plumbing 能否继续，不能写入 C1/C2 evidence。
- Comparator drift：21-scalar order、ridge solver、normalizers、coefficients与 hashes 在 falsifier 前冻结。
- Extreme imbalance：使用 gain-weighted prompt-balanced hinge；neutral zero loss；不引入 post-hoc class weighting。
- Small falsifier：严格 one-shot conjunctive gate并报告 prompt-cluster intervals；失败不重切 split。
- Latency duplication：复用 producer states，不运行第二个 producer；unfused hook 仅作 offline implementation，online fused claim 需新 review。
- Concurrent formal Direct jobs：不得修改其 pinned trainer/producer，直至它们与依赖汇总完成。
